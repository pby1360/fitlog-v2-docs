# AI 자세 분석 프로토타입 설계

## 개요 및 관련 PRD

[요구사항](PRD.md)을 기준으로 정리한다.

## 기술 설계

2026-08-27 로드맵의 계획이다. 첫 두 주에 로컬 MediaPipe Pose 스쿼트 분석으로 무릎 각도와 깊이를 산출한다. 3주 차는 휴대폰 영상에서 서명 URL을 통한 Cloud Storage 업로드까지, 4~5주 차는 별도 FastAPI·MediaPipe 서비스가 구조화된 판정을 내리는 단계다. 6주 차는 Spring 백엔드와 분석을 비동기로 연결하고 세트에 결과를 연결한다. 7주 차는 웹의 업로드와 일지 상세에서 휴대폰으로 흐름을 확인한다. 8주 차는 영상 1건당 처리·저장·전송 비용을 실측한다.

## 설계 대안

직접 비동기 호출(WebClient)과 Cloud Tasks/Pub/Sub를 원본에서 후보로 제시했다. 호출·재시도·상태 전이 계약과 제품 범위는 승인 대기다.

## 데이터 모델

기획의 `WorkoutRoutineSet.analysis_result`와 로드맵의 `WorkoutSessionSet.analysis_result`는 계획 항목이다. 현재 기준 커밋의 엔티티 및 Flyway V1–V7에 대응 컬럼이 없다. JSONB 저장 여부와 스키마는 설계 승인 후 결정한다.

## API 계약

업로드 API와 분석 서비스의 `POST /analyze`는 계획상의 진입점이다. 업로드·상태·분석 JSON의 구체 계약은 미정이다.

## 예외 처리 및 보안

실패·재시도·삭제 정책과 영상의 보관 기간을 설계해야 한다. 원본은 분석 후 유한 기간의 삭제와 인스턴스 상한, 예산 알림을 검토 항목으로 남겼다.

## 테스트 계획

로컬 스쿼트 분석 → 휴대폰에서 업로드 → 서버 분석 → 일지 표시의 단계별 결과를 확인한다. [DoD-2](../../product/RELEASE_CRITERIA.md)가 최종 판정 근거다.

## 위험 및 롤백

개인 영상의 저장·전송, 사용당 비용과 데이터 삭제가 핵심 위험이다. 정식 기능 노출 및 스키마·저장소 롤백 방법은 구현 설계에서 승인한다.
