# 신규 기능 아이디어

로드맵에 없던 기능과 검토가 필요한 제안을 등록한다. 새 항목에는 `FEAT-0001` 형식의 다음 미사용 ID를 부여한다. 승인·반려·철회 여부와 관계없이 기존 ID를 재사용하지 않는다. 후보 행만 등록한 상태에서는 개발 승인이나 실행 대기열 편입이 발생하지 않는다.

## 등록과 검토

1. 아래 양식을 복사하고 제안 원문, 문제와 기대 효과를 남긴다. 기존 기능을 확장하는 제안은 해당 기능의 요구사항과 설계를 연결한다. [기능 목록](../features/README.md)
2. 사용자가 구체화를 요청하면 같은 ID로 [PRD 템플릿](../templates/PRD_TEMPLATE.md)과 [Tech Spec 템플릿](../templates/TECH_SPEC_TEMPLATE.md)을 작성한다. 기존 기능과의 중복, 모호한 요구사항, 웹·서버 변경 범위, DB·API 변경 필요성, 보안·개인정보 영향, 수용 기준, 테스트 계획, 선행 작업을 각각 명시한다. 사용자 확인이 필요한 사항은 PRD에 남긴다.
3. 사용자가 범위와 요구사항을 승인하면 승인 근거와 PRD·Tech Spec을 링크한다. 승인된 기능만 같은 ID로 [백로그](../status/BACKLOG.md)의 P0~P3 중 한 곳에 등록한다. 제품 정책이나 범위가 바뀌면 사용자에게 다시 승인을 받는다.
4. 자동 개발 허용은 별도 증거로 남긴다. 해당 허용 범위와 승인 명세 SHA를 확인한 뒤 대기열 상태를 갱신한다. [대기열 등록과 실행 조건](../operations/DEVELOPMENT_WORKFLOW.md#신규-기능과-실행-대기열)

## 등록 양식

아래 항목명을 복사하고 `### FEAT-NNNN 기능명` 아래에 값을 기록한다.

| 항목 | 작성 내용 |
| --- | --- |
| 기능 ID와 이름 | 고유 ID와 기능명 |
| 사용자가 겪는 문제 | 어떤 사용자가 어떤 상황에서 겪는 문제인지 |
| 기대 효과 | 사용자가 얻을 이점과 가능한 확인 지표 |
| 관련 기존 기능 | 기존 PRD·Tech Spec·기능 목록 링크 또는 해당 없음 |
| 최초 제안 내용 | 제안자의 원래 요청과 출처. 검토에서 바뀐 내용은 별도 기록 |
| 요구사항 검토 상태 | 검토 대기, 구체화 중, 검토 완료 또는 보류 |
| 승인 여부 | 미승인, 승인, 반려 또는 철회. 확인한 승인 근거와 범위 명시 |
| 관련 문서 링크 | PRD, Tech Spec, 승인 기록, 등록된 백로그 또는 해당 없음 |
